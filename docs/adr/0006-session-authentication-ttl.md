# ADR 0006：请求身份建立前确认当前会话仍有效

日期：2026-10-26。适用现有Hash会话与原角色策略，不包含生产部署。

## 问题和决定

7AE只修新会话发布顺序，历史含id无TTL Hash仍可能被旧过滤器读取、授予身份后续期。旧过滤器也忽略续期false，读取后被删除的快照可能仍用于当前认证。

保留原HGETALL、DTO映射、ACTIVE及当前角色读取；在建立两个请求上下文前新增单key Lua。当前key必须仍为Hash、HGET id与刚读取的原始id字符串一致，再要求PTTL>0并成功PEXPIRE。只有返回1才建立身份，其他结果不认证，Redis命令异常沿原依赖失败边界向外传播，finally清理请求上下文。

无TTL/临界0且仍匹配原身份的key尽力DEL，不因清理失败授予身份。key缺失、变类型或id变化时返回0且不续期/删除替换数据。大ID不转换为Lua number，ttl参数沿用原分钟常量等值毫秒。

## 为什么不只先getExpire

单独检查TTL、读取Hash再续期仍有跨命令检查与使用间隙。条件续期将当前id、TTL与写过期放在同一个key的隔离执行里，避免给已丢失或换身份的快照授予本次身份。它不冻结外部DB角色读取或后续整个业务请求。

## 边界

只按请求处理token，不扫描/导出/批量删除历史会话；未呈现的旧key可能继续留存。无TTL有效账号会话将不再自动“修好”而认证，需重新登录。清理失败可留无TTL键，但当前更新实例会继续拒绝它；旧应用实例仍会接受，发布需完整升级，不把混跑或回退旧门禁称为安全方案。

账号禁用、无有效角色等原Java删除支路未条件化，本阶段不宣称所有旧清理竞态已解决。DB状态/角色查询并非冻结快照；Lua认证判定后发生登出或角色变化，不回溯撤销已经判定的请求。ACL需允许EVAL/EVALSHA/TYPE/HGET/PTTL/PEXPIRE，DEL用于尽力清理；Redis异常可使请求失败，不回退到旧非安全认证。
