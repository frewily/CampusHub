# ADR 0004：可选发布编号使用同事务数据库账本

日期：2026-10-15。状态：本阶段采用，范围与证据见[Phase7N](../refactor/36-phase-7n-blog-publication-keys.md)。

7M已把动态与Feed意图放在同一MySQL事务，但未知提交结果后的客户端重发仍可能建立新动态。单独的Redis去重锁会增加与内容提交不同步、过期和恢复窗口，不能仅凭锁存在判断是否成功。

选择可选 `Idempotency-Key`，按当前用户与大小写敏感编号建立持久唯一账本；保存版本化有效请求摘要和原ID，不缓存全文/认证。占位、动态、Feed意图和完成ID同一InnoDB事务；竞争后以当前读检查摘要与完成ID，原内容不同即409。旧无编号路径不改变。

重放采用共享当前读 `FOR SHARE`：已提交账本不可变，独占锁没有必要；四请求实测曾复现重复INSERT共享锁再升级独占读的死锁，修正后同时保留旧RR快照可见性和四请求同ID断言，不通过吞掉错误或无限重试来掩盖。

代价：成功账本永久增长，SQL竞争与5秒语句timeout不能保证延迟；回退忽略编号的旧应用会丢失协议保证。没有TTL/自动清理、跨库/HA、全Feed重建或全局exactly-once。只有需要明确的过期/容量协议后再设计清理，不能直接删账本或增加中间件来声称解决问题。
