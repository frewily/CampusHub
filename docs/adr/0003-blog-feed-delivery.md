# ADR 0003：以数据库 outbox 恢复动态 Feed 投递

状态：本阶段采用，范围与证据见[Phase7M](../refactor/35-phase-7m-blog-feed-delivery.md)。日期：2026-10-14。

动态发布已有MySQL内容事实与Redis收件箱，但先提交内容再同步投递会出现“内容存在、请求失败”。本项目已用数据库outbox处理取消补偿与缓存失效，当前没有需求证明必须为Feed增加专业消息中间件。

选择将收件人快照和固定score与内容同事务保存；提交后快速尝试及有界后台恢复使用同成员/同score ZADD，条件确认后删除待办。受众无需在重试时重查，Redis重复副作用可重放，因此暂不增加租约。无需微服务、分布式事务或更换现有Redis类型。

代价：关系快照/入队成本随受众增长，后台有限批次会有积压，不承诺延迟或容量；没有永久投递历史、全Redis丢失重建、客户端发布幂等、跨页快照或HA。只有出现明确的规模/隔离需求并有实测依据时再评估消息中间件；此次没有做实际压测。
