# Phase 7C：一级评论的一层直接回复

日期：2026-10-10。应用基线：`cf70aae0692d7602076d55f7820e0f5a75d80d2c`。按原始 Comment 领域关系，在 7B 一级评论闭环之上增加直接回复发布与独立列表；不同时展开删除、审核、通知或多级回复。

## 范围和兼容

- 新增 POST /blog-comments/{commentId}/replies，USER/MERCHANT/ADMIN 认证后均可发布；GET 同一路径由全局安全链要求认证。commentId 为正数，JSON 仅接收非空白、≤255 的 content；未知作者、动态、父评论/回复目标、状态、计数、主键和时间字段忽略。
- 目标必须为 status=0、parent_id=answer_id=0 的一级评论，且其动态存在。举报/隐藏/NULL 状态、回复、孤立根评论和不存在的 ID 对读写均为 404；不提供绕过规则的管理员发布路径。
- 所属 blog_id 由父评论派生；作者来自会话，parent_id=answer_id=路径 ID，liked/status=0。创建先定位根评论，固定先锁动态、再锁相同动态下仍正常的根评论（当前读），插入/计数增量/时间回读同事务。失败回滚，服务内部数据库异常为通用 500，不输出驱动细节；影响行数异常为 422。
- 列表同时绑定派生 blog_id 和 parent_id=answer_id=commentId，仅返回 status=0 的直接回复。size 默认 20、范围 1..50，beforeId 可选正数；ID 降序、严格小于游标，size+1 探测。响应复用 BlogCommentItem/BlogCommentPage 的字符串 ID 白名单，nextBeforeId 为本页最后实际返回的 ID，无下一页时省略，不提供 total。
- 读取在只读 REPEATABLE_READ 事务内；同请求快照不代表跨页快照。原一级评论列表仍只返回根评论，公用分页组装提取为私有辅助方法，不改变 7B 语义。
- 复用 tb_blog_comments 与 V007 复合索引，本阶段无 V008、新表或额外 DDL；已有库仍需按原阶段先备份审查、应用 V006/V007。不回填历史关系/计数，不自动删除或纠正旧异常行。
- API 目录更新为 41 个应用端显式映射、12 个 Controller；两个管理端 GET 单列，source_revision 仍只表示目录初建来源。对四条评论/回复路由及方法级授权加目录门禁。

动态 comments 继续为旧聚合字段，对新一级评论与回复各增一，不等于当前可见根/回复数；旧 NULL 仅按 0 增量处理，不重算历史。内容是不可信文本，展示端须转义；没有幂等键，提交后响应丢失时盲目重试可能重复。以上限制不是生产容量、索引收益、全客户端兼容或任意外部写入无死锁的保证。
