# Phase 7I：支持纯文字校园动态

日期：2026-10-13。应用基线 `6e0580d1065b8036281709b4111f39b9865169bb`，本轮重新从远端 main 核验、恢复干净独立副本。原教学仓库和旧临时副本未修改；预存未跟踪文件保留。

现有 `POST /blog` 的纯文字校园动态最小兼容行为已实现，选定本轮验证完成。范围清晰提交后由未参与实现的 Luna 独立静态审查，再普通推送并读回远端；最终提交 SHA、审查和推送状态在交付对话报告，不在此提前宣称。

## 最小用例与请求规则

- `shopId` 省略或为 `null` 时代表无关联门店校园动态。此时 `images` 可省略、为 `null`、空串，或是 `String.trim()` 后为空白的字符串；这些输入统一映射为非 null 空字符串 `""` 再写入现有动态记录。
- 当 `shopId` 为正数、动态关联门店时，`images` 仍必须非空白。旧带图校园动态和旧门店关联动态保持可用。
- `images` 原始字符串长度上限为 2048 个 Java UTF-16 单元，且在空白归一化前校验。因此 2049 个空格也必须拒绝；合法的非空图片原串保持原样，不 trim、不改写。
- `title` 必须非空白且不超过 255；`content` 必须非空白且不超过 2048。正数 `shopId` 约束不变。
- 沿用 USER/MERCHANT/ADMIN 发布权限。匿名、停用账号或无有效角色身份为 401。作者取自认证会话；客户端提供的 id/userId、作者、计数、时间等未知字段忽略。
- `images=""` 是非 null 值，在现有 NON_NULL 序列化配置下仍正常输出，不得被省略。客户端自行根据空值显示无图；本阶段不制作 UI。

## 兼容、结构与响应边界

- 只复用 `POST /blog`、现有动态表和 `images` 列；不增加路由、表、列或数据库迁移。V001–V009 部署状态不变，应用路由数仍为 46、Controller 数仍为 13。
- 详情、热门、本人列表、指定作者列表和 Feed 延续旧 Entity 响应。本阶段不改全局响应格式或 ID 字符串化。
- 不改变点赞存储，不新增图片来源、HTML/XSS 校验或内容审核，不把空 `images` 变成其他字段或 JSON `null`。
- MySQL 写入后 Redis Feed 失败窗口、非原子投递及遗留点赞问题仍在本阶段范围之外；本阶段不声称交付完整内容平台。

## 调用链与部署回退

`BlogController.saveBlog` 先对 `BlogCreateRequest` 进行 Bean Validation；条件图片要求通过服务端 `isStoreImageValid` 的 `@AssertTrue` 计算，不接受客户端覆盖，`@JsonIgnore` 排除同名 JSON 属性。`ApiModelMapper.toBlog` 在校验后将无图值映射为 `""`，保持非空图片原串，再调用既有 `BlogServiceImpl.saveBlog`；作者取会话，MyBatis 写入后沿用已有 Feed 投递。

本阶段不升级框架，不改变 schema、V001–V009 或部署初始化。回退旧应用不需要反向 DDL，不删除或伪造已发布纯文字内容；旧后端的既有读取代码可读取空串，但旧发布校验会重新要求图片。不能据此声称旧/新客户端 UI 已适配无图内容。
