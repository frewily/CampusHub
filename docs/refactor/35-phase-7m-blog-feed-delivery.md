# Phase 7M：动态发布与 Feed 可恢复投递

日期：2026-10-14。基线 `aad46ed3abe2db55ae2aca5c7c0aab3e96e9934b`。只解决发布事实已保存、投递故障却被报成发布失败的窗口；复用本项目数据库outbox思路，不引入专业MQ或新业务路由。

## 先复现，再修改

在未改生产代码时，对自建真实MySQL运行新增发布IT。Redis写收件人Feed抛出故障时，独立MyBatis读取确认动态已提交，但 `saveBlog` 抛出异常，新用例失败。这是实际已存储内容与请求失败语义不一致，不是只看代码猜测。按系统化调试定位后，将发布和投递意图放入同一实际可写事务。新mock测试两处匹配器混用错误也已定位修正，不删断言来通过。

另用真实MySQL复现内部绕过代理时“只在入队处检查事务”为时已晚：预期0个动态实际留下1个。因此统一事务门禁同时置于发布首条SQL之前和入队处；正常请求必须使用Spring事务代理，不把门禁当作自动开启事务。

## 发布契约和受众

保留 `POST /blog`、原DTO、字段白名单、三角色与200响应 `Result.ok(blogId)`。成功表示动态和本次投递意图已提交，**不表示所有关注者已收到，更不表示已读**。没有发布幂等键；客户端断连、超时或不知道提交结果时再次POST仍可能生成新动态，不能声称重试发布不重复。

事务内保存动态，读取MySQL关注关系快照，去重并保存每位收件人的待办。受众是该次DB查询观测到的关注关系，不是提交时全局订阅快照；不在重试时重查关注，不回填之后新关注者，不按Redis的follows投影决定受众。非法非正收件ID拒绝并回滚；不检查每个历史正ID账号是否存在，也不修历史脏关系。

`tb_blog_feed_delivery`（V011）以 `(blog_id,recipient_user_id)` 为主键，保存固定 `score_millis`、attempts、安全异常类名、下次重试及创建/更新时间。固定分数在本次发布入队时采样，所有收件人一致，正且不超过2^53−1；不是DB提交顺序、单调全局时钟或延迟指标。没有外键/当前状态join，动态撤回不删意图，后续Feed读仍过滤撤回行。

任何动态/意图插入失败或真实影响行数非1，事务整体回滚，Redis没有提交前副作用；数据异常转换无cause的通用500，非1行为422。无关注者时只提交动态。Service的真实可写事务与同步状态由入队门禁要求，不在没有事务时退化为半成功写入。

## 提交后和恢复

提交后回调最多快速尝试32位收件人，只写Redis，不用仍绑定的JDBC连接删待办或记录确认。每个目标的普通运行时故障单独吞掉并只记安全类名，不把已提交动态改报失败；全部意图仍由后台确认。受众快照读取/插入成本仍随人数增长，回调网络尝试有界但不承诺低延迟，未进行实际压测。

后台默认启用，每次轮询间隔5秒，每批最多32条到期意图，顺序为due/blog/recipient。先 `ZADD feed:<recipient> <固定score> <blogId字符串>`，true或false都代表命令已确认，null不确认；随后按blog/recipient/score条件DELETE匹配待办。Redis故障记录安全异常类名（至多64字符）、失败数最多1000000及UTC下次重试+5秒；仍保留意图，不转入终止状态，不无限忙轮询。单行或轮询异常不会抛出到发布请求，不让一条失败阻断本批其他目标。XML/注解SQL timeout5秒不是SLA。

Redis成功、DB确认失败或进程在二者之间退出时，匹配意图可重放：相同成员与分数重复ZADD不制造第二个成员，也不因重试刷新排序。无租约：并行worker可能重复执行命令，但完成/失败都条件匹配，失败UPDATE不会复活被其他worker删掉的意图。这里不是跨DB/Redis原子事务、通用exactly-once或客户端发布幂等。

确认后删除的待办不是永久投递历史，Redis之后丢数据不会自动重建。命令成功也不代表AOF已刷盘/副本已同步，不增加HA、历史Feed重建/补投、冻结分页、通知、后台查询或新诊断指标。认证仍依赖Redis；本用例不保证Redis整体离线时仍能登录/发布。实际应用重启验证也不等于硬杀、断电或HA验证。

## 部署和回退

新库bootstrap为schema→V001…V011→合成seed。现有库先备份、核对已知InnoDB结构并人工审查应用V011，再升级应用；已有卷重启不自动迁移。CREATE IF NOT EXISTS可重复保留待办，不自动校验/修复同名错表，不回填旧动态。

`BLOG_FEED_DELIVERY_WORKER_ENABLED`默认true，application、Compose和示例配置已接入；test profile 默认false，离线配置契约测试先证实遗漏再转绿。false只暂停后台轮询，不取消意图或关闭提交后快速尝试。积压期间不能宣称已完成全受众投递。该开关未加入新HTTP管理接口。

回退到7L等认识撤回标记的旧应用可保留表，但旧应用不消费这些待办、也不再建立新待办，可靠性会降级；需显式安排兼容worker/积压收口或采用修复发布。禁止DROP表、删除pending来伪装回退完成。7J及更旧仍忽略V010撤回标记，不可直接回退。

API目录仍48条/13个Controller，BlogController10条；只更新发布成功语义与阶段边界。不升级Java8/Boot2.7.18/MyBatis-Plus3.4.3。
