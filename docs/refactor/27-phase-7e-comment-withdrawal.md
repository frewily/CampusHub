# Phase 7E：本人一级评论逻辑撤回

日期：2026-10-11。前置源码为 7D 最终提交 `d39300bdd6a2ba929b3f950a050278af8b281cb3`；从干净工作区开始，原始教学仓库和要求文档不修改。

## 最小范围与不变量

- 新增 `DELETE /blog-comments/{commentId}`，正 Java Long，无 body；认证及 USER/MERCHANT/ADMIN 方法 guard，所有角色一律仅本人、无商户/管理员覆盖。HTTP 200 仅 `{"success":true}`。
- 只接受所属动态存在、parent_id=answer_id=0、status 为 0/3 的本人行；非本人（含已撤回）、缺失目标/动态、回复、不支持的关系/状态统一 404。普通定位之后先锁动态，再当前读锁一级评论并复核归属/关系/状态。
- 0→3 与动态 comments 减一同事务，NULL/0 下限为 0；3 重复不写入/扣计数。Mapper 数据库异常为通用 500、无驱动 cause；影响行数异常为 422、整体回滚。
- 原文、根关系及全部回复行/状态保留，不级联修改或扣回复计数。根从一级列表排除，提交后开始的新请求对根下回复读取/创建为 404；回复作者仍可用 7D 独立撤回本人回复。并发 RR 读取可能看到旧快照；先完成的创建仍可能成功，不保证撤回与创建并发时全部创建都失败。
- 复用 7D 状态 3 与 V007，无 V008、新表/列/索引或结构迁移；fresh schema 仅补列说明。已有库仍先具备 V006/V007，已有卷不自动更新注释，回退应用不恢复状态/计数。
- 同步 API 表格/机器目录/源码门禁为 43 条应用显式映射、12 个 Controller、6 条评论/回复/撤回映射，独立管理端两个 GET 不计入；source_revision 保持目录初建来源。

无物理删除、级联、恢复、管理员审核、多级回复、通知、前端、创建幂等键、历史计数/关系修复或生产容量结论。comments 是旧聚合增减，不等于可见数；保留原文不等于隐私数据抹除。
