# Phase 7D：本人直接回复逻辑撤回

日期：2026-10-11。前置源码为 7C 提交 `bb22c3614cc966a62be2bd40d257a2d899c91387`；从干净工作区开始，原始教学仓库和要求文档不修改。

## 最小范围

- 新增 `DELETE /blog-comments/replies/{replyId}`，正 Java Long 路径，无 body，认证并允许 USER/MERCHANT/ADMIN。所有角色均只操作本人，ADMIN 无覆盖权限；不提供客户端作者/动态/状态入口。
- 仅符合 parent_id>0、answer_id=parent_id、状态 0/3 的本人行，所属动态必须存在。不要求父评论仍存在/可见，因此允许本人符合格式的旧孤立回复定点撤回，不是历史批量清理。非本人、一级评论、不支持的关系/状态、目标/动态缺失统一 404。
- 普通定位本人行后先锁动态，再用当前锁定读复核同动态/同作者/直接回复格式/状态；0→3（作者撤回）和动态 comments 递减同事务。3 重复成功不写入、不扣计数，原文/关系保留。SQL 异常通用 500，无驱动 cause；影响行数异常 422、整体回滚。
- comments 旧聚合仅递减一次，NULL/0 下限零，不重算历史；不保证等于可见数量。列表保持 status=0，提交后开始的新读取不返回撤回行，但已建立 RR 快照可能看到旧版本。
- 复用现有 TINYINT 和 V007，无 V008、新列/索引或结构迁移，fresh schema 仅更新状态列注释。已有库仍先具备 V006/V007，旧卷注释不自动更新。回退应用不恢复状态/计数；未来管理工具必须识别状态 3，不得混同状态 2。
- 机器目录、逐接口表格及源码门禁更新为 42 条应用显式映射、12 个 Controller、5 条评论/回复/撤回映射，管理面两条 GET 单列；source_revision 保持目录初建来源。

无一级评论撤回、物理删除、恢复、级联、多级回复、管理员审核、通知、点赞、创建幂等键、前端、历史计数/关系修复或生产容量保证。新增 DELETE 的重复成功不代表创建 POST 安全重试。保留原文不等于隐私抹除协议。
