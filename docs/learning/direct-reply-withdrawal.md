# 本人直接回复撤回：权限、幂等与事务计数

Phase 7D 只增加 `DELETE /blog-comments/replies/{replyId}`，不是完整删除/审核系统。逻辑撤回保留原文和关系，仅把正常直接回复状态从 0 改为 3；不物理删除，不提供恢复接口。原来的 1（举报）、2（隐藏）和 NULL 含义不变。

## 角色权限不等于资源归属

USER、MERCHANT、ADMIN 都能调用，但 SQL 必须同时约束会话作者。没有管理员覆盖权限，也不能凭商户成员关系撤回其他人的回复。不存在、非本人（包括已经撤回）、一级评论、answer 与 parent 不同、其他状态、动态缺失统一 404，避免接口直接区分他人内容的存在性。

撤回的资格是本人、parent_id>0 且 answer_id=parent_id、status 为 0/3、动态存在。不要求根评论仍存在/可见：在根被隐藏后也允许作者撤回本人内容。符合格式的本人旧孤立回复可被定点撤回，但这不是历史关系修复或批量清理；没有开放客户端作者/状态/动态字段。创建的可见根约束仍保持原样。

ID 必须为正 Java Long，客户端大 ID 用字符串构造路径。没有请求体，HTTP 200 只返回 `{"success":true}`。匿名、停用或没有有效角色的账号为 401；账号登录并不意味着目标归属合法。

## 为什么要定位后再次锁定

普通定位仅取得本人目标的 id/blog_id；这个结果可能来自旧快照。事务先锁动态，再对同动态/同作者/相同直接回复格式的 0/3 状态行作 FOR UPDATE 当前读。若定位后作者、动态、关系或状态变化，则复核失败为 404。按当前状态决定写入，而不是按旧对象判断。

与已有创建路径保持“动态→评论”锁顺序，同一动态的创建、撤回都通过动态锁串行维护计数。第一次 0→3 后递减计数，两步都检查影响行数并共同提交/回滚；SQL 异常统一 500，不暴露驱动原因，非预期行数为 422。查询有既有 5 秒超时；不承诺任意外部 SQL/未来管理路径无死锁。

## 幂等边界与旧计数

当前锁定读看到 3 时直接成功，不再次改状态/计数，支持响应丢失后的本人重试。并发多次撤回也只能进行一次 0→3。此性质仅适用于该接口和条件仍成立的目标，不代表创建 POST 获得幂等键；账号失效、目标消失或外部状态变化后仍可返回错误。

动态 comments 延续旧聚合，仅对此次正常→撤回递减一，NULL 或零按零下限处理。它不是当前可见数量，也不修复历史：历史行可能从未计入聚合，不能依靠撤回重新计算准确总量。零不下溢依赖 SQL 条件分支及默认 Connector/J 匹配行数语义；已有 NULL/0/1/7 的真实数据库测试和目标版本 HTTP 验证，不支持任意自定义 JDBC 参数保证。

列表仍只读 status=0，撤回后开始的新请求不会返回该行；已建立只读 RR 快照的并发请求可能看到撤回前版本，跨页也无固定快照。保留原文意味着不是隐私数据抹除协议，管理员/备份/数据库访问仍可能看到内容。

## 迁移与回退

复用现有 TINYINT 和 V007，没有新列、索引或 V008。fresh schema 仅补状态列说明；已有库不用为本阶段执行结构迁移，但须已具备 V006/V007，已有卷不会自动更新列注释。3 是应用新增语义，未来审核/迁移工具须识别它，不能混同 2 或自动恢复。

回退旧应用不还原状态/计数；7B/7C 的 status=0 列表仍排除 3，但旧应用没有撤回入口。无需/不得自动把 3 改回 0，任何恢复或历史数据处理另定范围和授权。无一级评论撤回、级联、物理删除、恢复、管理员审核、多级回复、通知、前端或生产容量结论。
