# 一级评论管理员隐藏：事务、审计与可见性

Phase 7F 为一级评论增加有限的管理员隐藏入口：

```http
POST /admin/blog-comments/{commentId}/hide
Content-Type: application/json

{"reason":"违反社区规则"}
```

这是业务应用端的 ADMIN-only 接口，由独立 `AdminBlogCommentsController` 暴露，不属于 Actuator 管理监听器。`commentId` 必须是正 Java `Long`；请求 `reason` 不能为空白，最多 255 个 Java UTF-16 单元，额外 JSON 字段会被忽略。操作人 ID 从登录会话取得，不接受客户端指定。USER/MERCHANT 即使是评论作者也会被拒绝；ADMIN 不要求是原作者。

## 锁顺序与当前读

隐藏、作者撤回和新建回复遵循先锁动态、再锁一级评论的顺序。隐藏先通过候选查询取得动态 ID，锁定动态后，再以 `FOR UPDATE` 当前读锁根评论并复核关系与状态。候选查询可能早于另一个事务的提交；锁后的当前读复核决定操作是否仍可执行。

InnoDB `REPEATABLE READ` 下，普通一致性读可能继续读取事务快照中的旧版本。锁定读是当前读，因此能复核已经提交的撤回或隐藏。新建回复若先取得动态锁，就可能先于隐藏完成；隐藏拿到锁后按当前状态复核。这确定了写入的先后顺序，但不保证并发普通读取立即看到新状态。

重复分支的审核行也必须用 `FOR UPDATE` 当前读：若另一个管理员在候选查询之后提交，当前读根状态已是 2，但普通快照仍可能看不到同时提交的审核行，误判为 404。真实 MySQL 固定竞态用例已证明去掉审核当前读会失败、恢复后通过；锁顺序是动态→根→审核记录，不仅是根状态复核。

## 原子状态变更与重复请求

首次隐藏仅适用于动态存在、`parent_id=answer_id=0` 且 `status=0` 的一级评论。一个事务完成三项写入：

1. 评论状态从 `0` 更新为 `2`。
2. 动态评论计数减一；计数为 `NULL` 或 `0` 时按零下限处理。
3. 插入审计记录，保存评论、动态、会话操作人、原因和 `from_status=0`、`to_status=2`。

每项必须恰好影响一行；否则整个事务回滚并返回业务错误 422。数据访问异常转换成不带底层原因的通用 500。原子事务避免出现已隐藏但未扣数、已扣数却无审计，或只完成部分修改的状态。

成功后再次调用时，仅当评论仍为 `status=2` 且存在 `comment_id`、`blog_id`、`from_status=0`、`to_status=2` 均匹配的审计行，才视为成功。首次成功的操作人和原因保持不变；换管理员或提交另一条有效原因重试，都不会覆盖审计或再次扣数。status=2 但没有匹配审计的旧记录不会被推定为本功能成功，返回 404。

回复目标、status 为 `1`、`3` 或 `NULL`、评论/动态关系无效、动态或评论缺失，以及没有有效审计的旧 status=2 均返回 404。根评论作者撤回仅允许 `status=0/3`，因此隐藏后的 status=2 根不能通过作者撤回入口处理。

## 内容保留与可见性

隐藏只改变根评论状态并将动态 comments 聚合计数减一。原评论正文、所有回复行及回复状态都保留；不级联修改回复，也不为被遮蔽的回复额外扣数。一级评论列表排除隐藏根；该根下新的回复列表读取和创建请求返回 404。已有回复作者仍可按 7D 规则独立撤回自己的回复。

计数是随历史写入维护的派生值，不是可见行数的实时保证。NULL/0 下限只避免计数变负，不修复旧数据或历史偏差；隐藏时也不回填其他评论。普通 RR 读可能暂时看到旧快照。回退应用版本不会自动把状态恢复为 0、补回计数或删除审计。

影响行数判断沿用项目默认 Connector/J 的匹配行语义，因此计数已经为 0 的减数语句仍返回匹配的 1 行。任意 `useAffectedRows` 覆盖未验证，不能把本轮 NULL/0 证据推广到改变驱动选项的部署。

## V008 与审计边界

V008 创建 `tb_blog_comment_hide_audit`，包含自增 `id`、`comment_id`、`blog_id`、`operator_user_id`、`reason`、`from_status`、`to_status`、`create_time`，并对 `comment_id` 建唯一约束。全新数据库初始化按 V001…V008 顺序建立结构。已有数据库应先备份、检查 schema，再于部署新应用前手动应用 `V008__add_blog_comment_hide_audit.sql`。

迁移使用 `CREATE TABLE IF NOT EXISTS`：不会修复同名但结构不符的表，也不会为既有 status=2 评论补造历史审计。不要把缺审计的旧隐藏记录自动归因给 7F。应用回退时保留审计表和记录，不自动恢复评论状态或动态计数。

审计表记录状态转换的操作元数据，不是防篡改日志；数据库管理员仍可修改它。7F当时没有回复审核；7O后来增加了直接回复隐藏，但不是通用回复审核系统。V008仍只记录一级评论隐藏，回复隐藏使用独立V013；本笔记中的V008单条/分页读取不包含回复审计。当前没有受保护的审计导出 API、隐藏内容快照、外键约束、恢复操作、举报工作流、通知、任意状态修复工具或完整管理后台。阶段范围分别见[Phase 7F](../refactor/28-phase-7f-comment-moderation.md)和[Phase 7O](../refactor/37-phase-7o-direct-reply-moderation.md)。
