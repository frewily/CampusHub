# 优惠券目录展示不是参加资格判断

7W将一个公开查询从旧技术分层提取到promotion：Controller处理正Long参数及Result，纯Java服务委托存储端口，MyBatis适配器复用原Mapper/XML。暂时复用Voucher Entity，不为一次拆分新造一套领域模型；写入、抢购与订单依赖仍待各自限定范围迁移。

旧SQL只筛shop_id和status=1，LEFT JOIN库存/活动时间，不再加当前时间或剩余库存条件。过期/未开始/零库存券和缺少库存行的已上架券仍可展示；普通券的库存/时间为null。数据库的status没有被SELECT，所以响应不带该字段，也不带创建/更新时间。数字ID/金额未改成字符串，不声称浏览器大整数无损。

目录可查到不代表一定有资格参与：原FlashSaleRules和Redis Lua仍负责资格/时间/库存，不能用结构重构顺手改变列表筛选。缺失门店可返回空数组，但没有额外门店join；没有排序、分页、缓存或实时库存保证。

LEFT JOIN不意味着库存表故障时可以忽略它。两个SQL表任一不可用时仍通用500，而不是空成功或降级；生产不新增错误吞并、回填或修复。认证链可能续期会话，业务查询不更新券/库存，不把整个HTTP说成完全没有Redis写。

验证分开看：mock证明协议/参数和依赖委托；真实XML/MyBatis组件证明上架筛选及列映射；全新Compose证明当前jar的实际HTTP装配。四类证据都不能外推生产容量或个人独立掌握。完整jar需clean构建，移除旧内部Java方法不承诺二进制兼容；无新DDL时回退7V不需数据回退，但更早迁移限制仍适用。
