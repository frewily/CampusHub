# 直接回复：关系派生、锁顺序与可见性

Phase 7C 在一级评论闭环上增加一层直接回复，不实现无限嵌套树或“回复某条回复”。原有 parent_id 表示所属一级评论，answer_id 表示回复目标；本用例把二者都设为同一个一级评论 ID，不能通过客户端任意组合这两个字段。

## 为什么只接收 content

POST /blog-comments/{commentId}/replies 的路径指向一级评论，body 只接收非空白、最多 255 个 Java 字符单元的 content。blogId 由目标评论派生，作者取会话；parentId/answerId 固定为路径 ID，liked/status 固定为 0。未知 JSON 字段被忽略，不能伪造作者、动态、回复关系、审核状态、主键或时间。

根评论必须满足 status=0、parent_id=0、answer_id=0，且它的动态存在。被举报(1)、隐藏(2)、NULL 状态、回复行、孤立评论和不存在的 ID 对读写均为 NOT_FOUND；不以它们作为可继续回复的节点。ADMIN 的内容发布能力仍遵循同一规则，不因管理员身份绕过可见性。

响应沿用 BlogCommentItem 的字符串 id/blogId/userId、content 和 createTime，不暴露 Entity。当前回复的目标由请求路径确定，因此没有新增回复对象中的 targetUserId、父评论内容或可泄露隐藏评论的详情。客户端大 ID 应用字符串传递；范围仍限于 Java Long，不支持无符号 BIGINT 的全部值域。文本原样存储，不当成可信 HTML，展示方必须转义。

## 普通读取不能代替写前锁定

普通查询只用于定位动态。如果“查询到正常根评论”之后另一事务把它隐藏，拿原对象判断会用到过时状态。

创建回复在同一个 Spring 事务内：

1. 普通查询正常一级评论，得到 id/blog_id。
2. SELECT 对应动态 FOR UPDATE；不存在立即失败。
3. SELECT 根评论 FOR UPDATE，重新要求相同 blog_id 和正常一级条件。这是当前锁定读，而不是复用前面的快照。
4. 插入派生关系的回复、原子增加动态 comments、回读数据库时间，检查写入行数后提交。

当前 SQL 只返回 id/blog_id，隐藏/非一级行由 WHERE 过滤为 null，不返回整行后依赖 Java Boolean 判断状态。MySQL IT 在第一次查询后用独立连接提交 status=2，证明锁定复查拒绝写入且不增加计数；这是定向竞态验证，不是任意网络/进程故障证明。

统一先锁动态、后锁根评论；一级评论写入也先锁动态，使同一动态的一级评论与直接回复串行修改聚合计数。将来新增审核/删除/迁移等写路径时必须协调锁顺序，不能假设本阶段已解决所有外部写入的死锁风险。热点动态的串行锁会限制吞吐，本轮没有容量或性能提升结论。

插入、计数更新或回读失败抛出运行时异常使事务回滚。服务内部的数据库异常转成通用 INTERNAL_ERROR，不输出驱动细节；影响行数异常为 OPERATION_FAILED。没有幂等键：提交成功后响应丢失仍可能导致重试重复发布，不能宣称 POST 安全重放。

## 列表、索引和计数含义

GET 同一路径要求认证，查询动态从根评论派生，同时绑定 blog_id、parent_id=answer_id=commentId、status=0。缺失/不正常的根评论为 404；正常根评论没有回复时为空页。跨动态、跨根评论、answer 不匹配、非正常状态的旧行不返回，不修复或删除它们。

size 默认 20、范围 1..50，beforeId 可选正数；ID 倒序、严格小于游标，取 size+1 条判断 hasNext。nextBeforeId 是最后一条实际返回的字符串 ID，没有下一页时因 NON_NULL 省略；不查 total。新增更大 ID 不会挤入下一次旧游标查询，但跨请求的状态/数据变化仍可能改变结果。

根评论、动态存在性与回复列表处于同一只读 REPEATABLE_READ 请求事务内，不保证跨页快照或审核状态实时传播。已有一级评论列表继续只返回 parent_id=answer_id=0 的根评论，不把回复混进去。

V007 的 (blog_id,parent_id,answer_id,status,id) 已匹配两类查询的等值前缀与 ID 范围，本阶段不增加 V008 或新库表。验证正确性/索引结构不是执行计划、索引收益或生产性能验收；已有库仍须先备份审查并应用原 V006/V007，重启不自动迁移。

动态 comments 延续聚合字段：本服务对新一级评论和新直接回复各增一；不等于根评论数、当前可见回复数或准确历史总数。COALESCE(NULL,0) 只是兼容旧值，不回填历史计数。回复失败不会半增计数，旧错误计数不会因此自动修复。

## 下一步边界

无多级回复、删除、审核操作、通知、点赞、限频/内容审查、幂等键或前端。若未来允许回复任意回复，需要明确定义根/目标解析、同动态归属、目标隐藏、树深度和计数规则，再单独扩展；不能直接开放客户端 answerId。
