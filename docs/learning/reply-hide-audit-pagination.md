# 回复隐藏审计分页：游标、保留记录与快照边界

## 实际开发照着走

先固定一个用例：当前ADMIN只看一个动态的回复隐藏审计。明确响应白名单、游标含义和空页语义，再写查询与测试，不顺手加入导出、恢复或全局列表。

可复制Prompt：

> 阅读7P的V013单条查询与既有根审计分页。只新增ADMIN按blog分页读回复审计：默认20/最大50，id倒序、严格beforeId、size+1，九字段元数据不join当前实体。V014只增加候选索引；先保留旧入口失败，再分别测试权限、真实事务、隔离HTTP和迁移重复/错形状边界。不要把索引DDL或合成数据当性能证明。

继续条件：源码/目录/接口表一致；只读、游标准确、旧接口不混对象；真实事务和接口证据完成后才提交审查。[7Q阶段记录](../refactor/39-phase-7q-reply-audit-pages.md)报告实际结果，测试数量不等于个人掌握。

## 游标是哪一个ID

一条回复有replyId，一次隐藏审计有自己的id。回复先创建、后隐藏，两种顺序可以不同；此列表按“审计ID”倒序，不按replyId或createTime。请求 `beforeId` 表示只取更小的审计ID，不包含边界本身。

请求示意：

```http
GET /admin/blog-comments/replies/hide-audits/of/blog/9007199254740995?size=20
authorization: <当前有效管理员会话>
```

只返回该blog的V013审计。items仍是7P九字段元数据，五个ID用字符串；不包括正文、当前可见性或账号资料。它与V008根评论分页是两个接口，不能悄悄混成一种对象。

## 为什么多取一条

size=2时查3条。若只得到0/1/2条，全部返回，hasNext=false，nextBeforeId省略。若得到3条，只返回前2条，hasNext=true，游标取“第二条已返回审计”的id；第三条只是探针，不能用它作游标，否则会跳过它。

默认size=20，最大50，因此查询最多21/51条。不查总量；没有当前动态或当前回复，并不代表保留审计也应该消失，所以不join当前业务表：无审计为空页成功，有保留记录就按条件返回。

## 一页稳定，不等于所有页冻结

普通SELECT在只读REPEATABLE READ事务中读已提交且对快照可见的行。写方未提交的审计不会进入本页；写方回滚后也不会凭空出现；较早建立的读快照可以继续看旧结果。

每个HTTP请求是新的一页事务，不承诺跨页冻结。自增ID通常先分配、后提交：一个较小ID可能很晚才提交，而读者已翻过它所属区间。只靠 `id < beforeId` 不能承诺完整无遗漏导出、全量一致快照或按提交时刻排序。

## 索引的证据边界

V014为V013增加候选 `(blog_id,id)` 索引，适配blog筛选和id排序，但建成索引不等于优化器一定采用，更不等于已经测出性能改善。这里不报告QPS、延迟或生产容量。

重复迁移按索引名跳过，同名但列顺序错误的索引不会被修复。已有库要先备份、核对形状并人工审查应用；缺V013应失败。DDL可能隐式提交和占用元数据锁，现有卷重启也不会自动迁移。回退应用可保留索引及审计，不删历史或恢复状态计数来模拟回滚。

大页边界测试会明确导入51条合成元数据，这不是51次真实隐藏，更不是压测。真实隐藏、mock权限、真实MySQL快照、Compose接口验收各说明自己的证据范围，不能相互冒充。
