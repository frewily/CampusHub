# 单条隐藏审计查询：身份、记录与快照

Phase 7F 的隐藏事务把评论状态变化、动态计数递减和一条 V008 审计记录放在同一事务中。7G 的职责是让 ADMIN 按评论 ID 读取这条已保存的元数据，不再执行审核决策或状态转换。

## 为什么按审计记录独立查询

审计行保存隐藏时的 comment、blog、operator、reason、from/to status 和时间。查询只按参数绑定的 comment ID 读取该行，并映射到固定八字段 DTO。它不 join 当前评论、动态或用户，因此不会把当前账号状态、动态关系或当前评论状态伪装成历史审计字段。审计行不存在时返回 404；不能因为当前评论 status=2 就推造一条过去的操作记录。

字符串 ID 保留 Java Long 的完整精度。响应只暴露明确列出的审计字段，避免将表实体直接序列化而意外泄露未来新增列。

`createTime` 是不含偏移的 LocalDateTime，默认 dev/Compose 的 JDBC 会话固定 UTC；prod 由 DB_URL 时区设置决定，不应把任意部署返回值都当成 UTC。比较 JDBC Timestamp 与 LocalDateTime 时应显式统一时区，避免 JVM 本地时区隐式加入八小时时差。

## ADMIN 授权与错误边界

Controller 使用 `hasRole('ADMIN')`。认证过滤链先决定请求身份是否有效：匿名、停用或未知/无效角色身份为 401；有效但只有 USER 或 MERCHANT 角色为 403。评论作者、原隐藏操作人都不会因此获得查询权限。路径 ID 不是正 Java Long 时为 400，找不到审计行为 404，数据库异常返回通用 500。

## 普通一致性读与 REPEATABLE READ

Mapper 使用参数绑定的普通 SELECT，超时 5 秒；服务方法开启只读 REPEATABLE READ 事务。没有 `FOR UPDATE`，因为查询不需要争抢隐藏事务的行锁，也不能读取另一个事务未提交的审计 INSERT。读取到的审计数据来自已提交事务。

InnoDB 的一致性读受事务快照约束：新事务的快照会看到创建前已提交的记录；如果该方法加入了此前已建立 RR 快照的事务，它可能继续读到较早版本。这个结果说明“当前快照可见什么”，不说明审计记录被删除或历史没有发生。使用新事务重试会取得更新的已提交快照。

## 能力范围

审计是数据库操作元数据，不是不可篡改证据；数据库管理员仍可修改或删除记录。V008 不为旧隐藏状态回填审计。该读取接口不改状态、不改计数，也不提供列表、导出、恢复、审核 UI 或完整管理后台。验证进度以[Phase 7G 阶段记录](../refactor/29-phase-7g-comment-audit-query.md)为准；真实 MySQL、目标 Compose、完整构建及目录门禁在本轮选定范围内通过，不能外推生产负载或全后台完成。
